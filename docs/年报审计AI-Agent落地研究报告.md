# 年报审计实质性程序到底稿及报告全流程自动化：AI Agent 落地研究报告

## 摘要

本研究报告面向审计零基础的技术开发者，致力于设计一款应用于年报审计"实质性程序-底稿编制-报告生成"全流程的 AI Agent。报告紧扣中国注册会计师审计准则（如 CSA 1312、CSA 1313、CSA 1314），深入剖析了各核心科目（货币资金、应收账款、存货、收入等）的审计执行逻辑。通过对当前人工审计实务（包括四大及内资所工作流、主流审计软件功能边界）的深度调研，精准拆解了人工操作的高耗时痛点。

基于上述分析，报告详细论证了 AI Agent 在函证控制、替代测试、数据分析、底稿生成等环节的自动化可行性，并规划了从数据获取到报告生成的全链路执行路径。进一步调研了国内外审计 AI 产品（如 MindBridge、CaseWare、鼎信诺 AI 版）及大模型（RAG、LangChain）的技术实现方案。最终，报告提出了从 MVP（最小可行性产品）到完整版本的阶段性实施路线图，为构建真正落地的审计 AI Agent 提供了一套系统、可操作的解决方案。

## 第一章：年报审计中"实质性程序 → 底稿 → 报告"完整执行逻辑

### 1.1 核心准则要求（CSA 1312, 1313, 1314）

* **CSA 1312 函证**：要求对应收账款、银行存款等存在认定的项目，必须实施函证程序，除非有充分证据表明其不重要或函证无效。未函证的必须实施替代程序。
* **CSA 1313 分析程序**：要求在风险评估、实质性程序及临近审计结束时使用。通过分析财务数据间关系（如毛利率波动、收入与运费的关系），识别异常波动。
* **CSA 1314 审计抽样**：要求在实质性程序中设计并选取样本。核心概念包括：总体定义、分层、样本量确定（基于重大错报风险和可容忍误差）、选样方法（随机、系统、货币单元抽样 MUS）。

### 1.2 实质性程序分类与执行内容

| 类别 | 具体程序 | 适用场景 |
| :--- | :--- | :--- |
| **细节测试** | **函证** | 验证银行存款、应收账款、应付账款的"存在"或"义务"认定。 |
|  | **盘点** | 验证存货、固定资产的"存在"认定。 |
|  | **检查** | 检查合同、发票、银行回单，验证"发生/准确性"认定。 |
|  | **重新计算** | 验证折旧、摊销、坏账准备、税费计算的准确性。 |
| **分析程序** | **趋势分析** | 对比本期与上期数据，识别异常波动（如收入激增但运费下降）。 |
|  | **比率分析** | 分析毛利率、净利率、周转率等核心指标。 |
|  | **合理性测试** | 基于业务数据（如水量电费）推算产量/收入合理性。 |

### 1.3 主要科目实质性程序详解

* **货币资金**：获取银行开户清单 → 发送银行函证 → 检查银行余额调节表 → 大额资金双向检查（资产负债表日前后）。
* **应收账款**：编制账龄分析表 → 发送函证（积极式） → 处理回函差异 → 未回函项目执行替代程序（检查期后收款、发货单、发票） → 测算坏账准备。
* **存货**：制定盘点计划 → 监盘（观察+抽盘） → 检查存货计价（加权平均/先进先出） → 测算存货跌价准备（成本与可变现净值孰低）。
* **收入**：分析毛利率变动 → 执行截止测试（查验资产负债表日前后的发货单/发票） → 检查重大合同（识别履约义务、确认收入时点） → 查验期后退货。
* **固定资产**：检查权属证明（房产证、车辆登记证） → 重新计算折旧 → 检查本期增减变动的合规性。

### 1.4 底稿编制标准流程（从审定表到明细表）

审计底稿的逻辑是**自底向上**的数据归集与**自顶向下**的逻辑校验，核心包括：

1. **审定表（Lead Sheet）**：宏观汇总。列示"上年末余额 + 本期未审数 + 审计调整 = 本期审定数"。这是底稿的"纲"。
2. **明细表（Breakdown/Working Paper）**：中观拆解。按科目二级明细（如应收账款按客户、固定资产按类别）列示，需与总账、明细账核对一致（Tie-out）。
3. **检查表/测试表（Testing Schedule）**：微观证据。记录具体的审计程序执行过程，如函证控制表、抽凭记录、重新计算表。
4. **交叉索引（Cross-reference）**：通过索引号（如 A1-1-2）将不同层级的底稿勾稽起来，确保证据链完整。

### 1.5 审计报告生成步骤

1. **试算平衡（Trial Balance, TB）**：将所有审计调整分录（AJE）录入 TB，确保资产=负债+权益，且利润表与资产负债表勾稽。
2. **附注编制**：基于 TB 中的明细数据，按照会计准则和披露格式要求，填写财务报表附注（如"应收账款按账龄披露"、"存货分类披露"）。
3. **关键审计事项（KAM）**：基于风险评估，确定需要在报告中沟通的关键事项。
4. **报告撰写与签发**：自动生成报告初稿 → 项目经理/合伙人复核 → 签发。

## 第二章：人工审计实务操作调研

### 2.1 典型工作场景（以四大及头部内资所为例）

* **年审高峰期（12月-次年4月）**：审计师驻场，通过 Outlook 或企业微信与被审计单位财务沟通，现场获取 ERP 数据或 Excel 数据包。
* **数据获取**：通常通过在被审计单位电脑上插入 U 盘，或直接远程访问其财务系统（如用友、金蝶）导出 Excel 或数据库备份。
* **底稿编制**：在 Excel 中手动粘贴数据，编写 Vlookup/Sumif 公式进行核对，使用 Adobe/扫描全能王处理抽凭获得的电子/纸质单据。

### 2.2 底稿编制具体操作流

1. **数据获取**：从客户财务系统导出科目余额表、序时账、辅助核算明细。
2. **数据清洗**：将不同格式（如用友导出的 TXT、金蝶导出的 Excel）标准化，处理合并单元格、文本格式数字等。
3. **公式计算**：在底稿模板中设置公式链接，确保"未审数"与"客户数据"联动。
4. **交叉索引**：手动输入索引号（如 `C-3-1`），且当底稿增减行时，需手动更新所有相关索引。
5. **复核**：项目经理（Manager）通过"追踪更改"或打印出来手工签批，检查底稿的逻辑与证据充分性。

### 2.3 审计报告编制人工流程

1. **TB 编制**：在 Excel 或审计软件（如 CaseWare）中维护 TB，录入调整分录。
2. **附注数据整理**：手动从 TB 中复制数据，粘贴到 Word 报告模板的表格中，极易出现格式错乱或数字不Link的问题。
3. **报告撰写**：基于去年的报告（Last year template）修改，更新数字、日期、管理层讨论分析（MD&A）相关内容。

### 2.4 当前行业使用的审计软件及功能边界

| 软件名称 | 主要功能 | 功能边界（痛点） |
| :--- | :--- | :--- |
| **鼎信诺** | 财务数据导入、底稿模板生成、自动生成试算平衡表。 | 数据接口依赖客户提供标准数据；自动化程度低，仍需大量手工填写；AI功能弱。 |
| **用友审计** | 作业管理、数据采样、底稿编制。 | 强于作业流程管控，弱于智能分析；对复杂会计准则（如新收入准则）的适配需手动调整。 |
| **ECPA** | 提供审计程序库、底稿范例。 | 更多是知识库和模板工具，非智能化执行平台。 |
| **CaseWare** | 国际主流，强大的电子工作底稿、自动生成报告。 | 国内适配性差（会计准则、报表格式）；价格昂贵；二次开发难度大。 |

### 2.5 人工操作常见痛点

* **效率痛点**：
  * 重复性复制粘贴（Copy-paste）。
  * 函证地址核对、收发跟踪极其繁琐且易出错。
  * 底稿索引号维护消耗大量时间。
* **质量痛点**：
  * 穿行测试样本量不足。
  * 替代程序执行流于形式（仅复印单据，未深度分析）。
  * 期后事项披露遗漏。

## 第三章：人工耗时拆解与自动化可行性分析

### 3.1 分科目耗时与自动化分析

| 科目 | 具体环节 | 人工耗时估算 (人天/项目) | AI Agent 替代比例 | 需保留人工环节 | 技术实现难度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **货币资金** | 银行函证制作与跟踪 | 2-3 天 | 80% | 函证地址真实性核验、异常回函判断 | 中（需对接工商/官网） |
|  | 银行余额调节表核查 | 1 天 | 90% | 重大未达账项的原因判断 | 低（规则引擎） |
| **应收账款** | 函证控制（制作/收发） | 3-5 天 | 70% | 回函差异的实质性判断 | 中 |
|  | 替代测试 | 2-4 天 | 60% | 检查单据的真实性（防造假） | 高（需OCR+多模态） |
|  | 账龄分析及坏账测算 | 1-2 天 | 95% | 坏账政策变更的会计判断 | 低（算法计算） |
| **存货** | 盘点计划与监盘记录 | 3-5 天 | 30% | 现场监盘（必须到场）、残次品识别 | 极高（需机器人/AR） |
|  | 计价测试与跌价测算 | 2-3 天 | 85% | 可变现净值的估计（需市场数据） | 中（需对接价格库） |
| **收入** | 截止测试 | 2 天 | 80% | 截止性舞弊判断（如提前确认收入） | 中 |
|  | 合同检查（关键条款提取） | 3-5 天 | 90% | 复杂合同条款的法律/商业实质判断 | 中（LLM应用） |
| **费用** | 波动分析/抽凭 | 1-2 天 | 70% | 异常费用的商业逻辑判断 | 低至中 |

### 3.2 综合自动化可行性评估

* **高可行性（>85%）**：账龄分析、折旧测算、试算平衡、底稿格式生成、数据清洗。
* **中可行性（60%-85%）**：函证自动化（需解决电子函证平台对接）、替代测试（需解决电子单据验真）、合同关键条款提取。
* **低可行性（<60%）**：存货监盘（物理动作）、复杂的会计估计判断、舞弊识别（需高度职业怀疑）。

## 第四章：自动化执行路径规划

基于以上分析，规划从"审计数据获取"到"审计报告自动生成"的完整执行路径：

### 4.1 阶段一：数据获取与标准化 (Data Acquisition & Standardization)

* **输入**：客户财务系统备份文件、Excel 导出数据、银行对账单 PDF、合同扫描件。
* **核心动作**：
  * 使用 **OCR** 和 **NLP** 解析非结构化数据（PDF/图片）。
  * 通过 **ETL 工具**将不同格式的财务数据（用友、金蝶等）清洗为标准的中间表（Standardized Chart of Accounts）。
* **输出**：标准化的审计数据库（包含科目余额表、序时账、辅助核算表）。

### 4.2 阶段二：风险评估与程序规划 (Risk Assessment & Planning)

* **输入**：标准化数据、上一年度底稿、行业数据。
* **核心动作**：
  * **AI Agent** 执行初步分析程序（如计算毛利率、流动比率），识别高风险领域。
  * 根据准则（CSA 1211）自动生成审计计划，确定**重要性水平**和**样本量**（基于 CSA 1314 抽样规则）。
* **输出**：审计计划书、风险评估底稿、抽样计划表。

### 4.3 阶段三：实质性程序自动执行 (Substantive Procedures Execution)

* **输入**：审计计划、标准化数据、外部数据源（工商、征信、天气/水电数据）。
* **核心动作**：
  * **函证自动化**：Agent 自动生成函证文本 → 对接**电子函证平台**（如中注协函证平台）发送 → 跟踪回函状态 → 对回函结果自动核对。
  * **分析程序**：Agent 自动生成同比/环比分析图表，标注异常波动点（如运费与收入背离）。
  * **抽凭与检查**：Agent 根据抽样规则从序时账中选取样本 → 自动向客户财务系统/共享文件夹请求对应单据 → 利用 **多模态 LLM** 检查单据合规性（如发票章是否清晰、审批流是否完整）。
  * **重新计算**：自动测算折旧、利息、坏账准备，生成调整分录（Draft AJE）。
* **输出**：执行过程记录、审计发现（Findings）、调整分录草稿。

### 4.4 阶段四：底稿自动编制 (Automatic Working Paper Generation)

* **输入**：实质性程序执行结果、调整分录。
* **核心动作**：
  * **RAG + 模板渲染**：基于审计证据，自动填写底稿模板中的"审计说明"部分（利用 LLM 生成自然语言描述）。
  * **自动索引**：算法自动维护底稿索引号（Cross-reference），确保勾稽关系正确。
  * **TB 更新**：自动将 AJE 更新至试算平衡表，校验报表平衡。
* **输出**：完整的、格式规范的电子审计底稿（Excel/PDF）。

### 4.5 阶段五：报告自动生成 (Report Generation)

* **输入**：最终 TB（已审定）、底稿中的披露信息、上一年度报告模板。
* **核心动作**：
  * **附注自动填充**：根据 TB 明细，自动填充财务报表附注表格。
  * **报告撰写**：LLM 根据关键审计事项（KAM）和审计结论，撰写报告正文及管理层讨论分析（MD&A）部分。
  * **合规性校验**：检查报告是否符合《中国注册会计师审计准则第 1501 号》格式要求。
* **输出**：审计报告初稿（Word/PDF），供合伙人复核签发。

## 第五章：技术实现方案调研

### 5.1 国内外审计自动化/AI 审计产品

* **MindBridge Ai Audit**：加拿大公司，利用 AI 进行**全量数据分析（100% Population Testing）**，而非抽样。核心功能是异常检测（Anomaly Detection）和风险评分。
* **CaseWare IDEA**：经典的数据分析工具，支持导入各种数据源进行查重、筛选、关联分析。
* **TeamMate+**：Wolters Kluwer 开发，强于审计作业管理和工作流，近年加入了 Analytics 模块。
* **国内产品**：
  * **鼎信诺 AI 版**：宣称利用 AI 进行智能预警和底稿生成，但实际体验仍偏向传统规则引擎。
  * **容诚事务所"智审"**：内部开发，利用 NLP 处理合同。
  * **信永中和"AI 审计平台"**：探索利用大模型辅助底稿编制。

### 5.2 大模型在审计领域的应用案例

* **合同审查**：使用 **GPT-4 / Claude** 或专业法律大模型（如 ChatLaw），通过 Few-shot learning 提取合同中的"履约义务"、"付款条件"、"违约责任"等关键条款，自动填写审计底稿中的"重大合同检查表"。
* **问询函生成**：根据审计发现的异常，让 LLM 自动起草给管理层的问询函（Management Letter）。
* **底稿说明撰写**：将审计证据（如"我们检查了发票号 123，金额 500 万，与合同一致"）输入 LLM，让其生成符合审计术语的"审计结论"。

### 5.3 审计底稿自动生成的技术路线

* **RAG (检索增强生成) + 审计规则引擎**：
  * **流程**：将审计准则、底稿模板、往年优秀底稿案例放入向量数据库（Vector DB）。当 Agent 需要填写底稿时，先检索相关规则和范例，再结合当前数据生成内容。
  * **优势**：减少 LLM 幻觉，确保输出符合审计规范。
* **结构化数据 + 模板渲染**：
  * **工具**：使用 Python `Jinja2` 或 `Docxtpl`。
  * **流程**：将 TB 和明细表数据转化为 JSON → 渲染到 Word/Excel 模板中。
  * **适用**：附注表格、审定表等结构化程度高的部分。

### 5.4 函证自动化的实现方案

* **电子函证平台对接**：对接**中注协银行函证区块链服务平台**或第三方平台（如提立德）。通过 API 实现函证申请、发送、回收数字化。
* **回函比对**：利用 **OCR** 提取回函 PDF 中的金额，与函证金额自动比对，标记差异。

### 5.5 审计抽样与异常检测的 AI 算法

* **Benford's Law (本福德定律)**：检测数字分布是否异常（常用于收入造假检测）。
